## 8.2 The Model-Update Response Protocol

Execute this three-step protocol whenever you notice output behavior changing after an AI platform update. Total time: approximately fifteen minutes.

### 8.2.1 The Three-Step Response Sequence

**Step 1: Rerun the Voice Bleed Diagnostic**

- [ ] Open your AI tool.
- [ ] Generate a test scene using your existing Dialogue Matrix for one character.
- [ ] Run the five-dimensional diagnostic from Chapter 1.
- [ ] Identify which dimensions have shifted.
- [ ] Log the specific changes in your Model-Update Log (see 8.2.2).

**Step 2: Adjust the Affected Modifiers**

- [ ] Open your Dialogue Matrix.
- [ ] For each drifted dimension, adjust the corresponding constraint statement:
  - Cadence flattened → Tighten the Rhythm Lock
  - Vocabulary widened → Lower the Ceiling Cap
  - Emotional register warmed → Adjust the Baseline Temperature
- [ ] Work one adjustment at a time.
- [ ] Regenerate the test scene after each single modification.
- [ ] Verify the correction before moving to the next adjustment.

**Step 3: Update the Library Version Tag**

- [ ] Confirm the voice holds across your three-scene stress test.
- [ ] Increment the minor version number on the affected Dialogue Matrix file.
- [ ] Note the date and the platform update that triggered the adjustment.
- [ ] Save the file. The archive holds the previous version; the active folder holds the corrected one.

### 8.2.2 Model-Update Log Template

Keep this log in your Library's top-level folder. One entry per platform update.

| Date | Platform Update | Dimensions Affected | Adjustments Made | Version Updated To | Verified? |
|---|---|---|---|---|---|
| [DATE] | [E.G., "GPT-4o spring update"] | [E.G., "Cadence, Emotional Register"] | [E.G., "Tightened Rhythm Lock; lowered Baseline Temperature by one increment"] | [E.G., v2.3] | [Yes / No] |
| [DATE] | [UPDATE] | [DIMENSIONS] | [ADJUSTMENTS] | [VERSION] | [Yes / No] |

### 8.2.3 Contingency: When You Cannot Run the Full Protocol Immediately

If a deadline prevents you from completing all three steps at once:

- [ ] Perform Step 1 only: generate a test scene and run the diagnostic.
- [ ] Log the findings in your Model-Update Log.
- [ ] Complete Steps 2 and 3 within forty-eight hours.

This ensures the shift is identified quickly and the correction follows in a controlled, documented sequence.
