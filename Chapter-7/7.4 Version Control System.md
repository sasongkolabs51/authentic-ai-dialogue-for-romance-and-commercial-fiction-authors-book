## 7.4 Version Control System

### 7.4.1 Decision Tree: Should I Increment the Version?

Use this tree every time you edit a voice asset.

**Step 1 – Did I change the document?**

- **No →** No version change. Save and move on.
- **Yes →** Proceed to Step 2.

**Step 2 – Does the change alter how the AI generates dialogue?**

- **No** (typo fix, reformatting, clarification of wording without changing the constraint) → Cosmetic change. No version increment. Save and move on.
- **Yes →** Proceed to Step 3.

**Step 3 – What level is the change?**

| Change Type | Definition | Action |
|---|---|---|
| **Major** | Added or removed an entire field, or fundamentally restructured the character's voice architecture | Increment the major number. Reset the minor number to zero. |
| **Minor** | Tightened a constraint, added a signature tic, refined a trigger response, or adjusted a parameter within the existing structure | Increment the minor number by one. |

**Version format:** v[major].[minor]

**Example progression:** v1.0 (initial build) → v1.1 (added Emotional Filter) → v1.2 (applied genre calibration) → v2.0 (cadence restructured for new arc stage)

### 7.4.3 Version Archive Protocol Checklist

Follow this every time you create a new version.

- [ ] The previous version file is moved into the "Archive" subfolder within the character directory.
- [ ] The archived file retains its original name and version number.
- [ ] The new version is saved in the active folder with the updated version number.
- [ ] The Version Change Log is updated with the new entry.
- [ ] The active folder contains only the most current version of each asset.
- [ ] You can open the archive and locate any previous version in under fifteen seconds.
